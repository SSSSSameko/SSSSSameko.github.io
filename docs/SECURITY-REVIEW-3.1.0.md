# 3.1.0 安全与稳定性审查

审查范围包括 React 前端、Node HTTP 服务、管理后台、微博抓取与 Cookie 保活、Caddy、systemd、安装脚本和发布流程。未发现 SQL 注入、命令注入、任意文件读取、存储型 XSS 或仓库内明文密钥。

## 已确认的边界

- 前端仅连接预配置地址或本机地址。备用 Cookie 和官方访问令牌只用于当前任务，任务结束后清除。
- 后台使用 scrypt 密码哈希、签名会话、HttpOnly/Secure/SameSite Cookie、CSRF 校验、登录限流和并发密码校验上限。
- JSON 请求、微博响应、头像、候选、奖项、中奖人、反馈和开奖记录均有容量或数量限制。
- 头像代理只允许微博与新浪图片域名，禁止重定向，并限制类型、大小、并发和缓存。
- 同一微博的并发载入会共享任务，短时复用完成快照；队列、单来源任务、订阅者、执行时间和完成响应体积均有上限。
- 微博入口返回不完整时会补扫备用入口；连续空页和重复页会提前停止。失效 Cookie 会轮换到下一条可用登录态。
- Cookie 统计区分已保存、可尝试、已验证、待验证、校验异常和临时隔离；被隔离的登录态不会同时计入当前已验证数量。
- 后台动态内容在写入 HTML 前统一转义，外链经过微博域名白名单。
- 服务端 CSP 禁止第三方脚本、内联脚本属性、框架嵌入和对象加载。
- systemd 让 Node 仅监听回环地址，限制内存、任务数和可写目录，并按日回收进程。Chromium 超时后会关闭上下文、终止确属当前 Profile 的残留进程并清理可再生成缓存。

## 产品与部署边界

- 公开的开奖记录保存接口允许客户端提交内容。过程哈希用于复查随机过程，不是不可伪造的第三方证明。
- “排除已中奖用户”和一分钟开奖间隔属于当前浏览器、当前任务的操作保护，不是跨设备的活动身份系统。
- 公开 API 仍可能遭遇分布式流量；应用内限流和资源上限保护单机，大规模攻击仍需云防火墙或 CDN/WAF。
- 生产环境必须使用独立且足够长的 `ADMIN_SESSION_SECRET`、`COOKIE_WRITE_KEY` 和来源指纹密钥，并让 Node 只监听 `127.0.0.1`。
- 生产环境默认启用 Chromium 沙箱（`WEIBO_BROWSER_SANDBOX=1`）。上线前仍须在目标服务器以真实 `www-data + systemd` 约束验证 Playwright、字体缓存、Profile 权限和退出后的进程清理；只有确认内核不支持时才可显式关闭。
- 服务器发布默认拒绝脏工作树，并从明确的 Git commit 生成归档；发布目录记录 `.release-commit`，未提交和未跟踪文件不会混入制品。非 Git 离线包必须显式启用例外开关。
- GitHub Pages 只能通过 HTML meta 下发部分 CSP；服务器托管版使用完整响应头。
- CSP 的 `style-src` 保留 `'unsafe-inline'` 以兼容 React 动态样式和后台图表；脚本策略不允许 `'unsafe-inline'` 或 `'unsafe-eval'`。

## 发布验证

- `npm audit --audit-level=low`：0 个漏洞。
- `npm test`：180 项通过。
- HTTP、服务器退出、微博多入口回退、Chromium 清理、内存浸泡和前后台浏览器测试均通过。
- 构建、许可证清单、JavaScript/MJS 语法和 `git diff --check` 均通过。

本文件记录当前代码的安全边界，不替代目标服务器的内核、反向代理、云防火墙和真实流量监控。
