# 3.0.0 安全审查

审查范围包括 React 前端、Node HTTP 服务、管理后台、Caddy 与 systemd 部署配置。当前没有发现可直接利用的 SQL 注入、命令注入、任意文件读取或存储型 XSS；项目没有数据库和用户文件上传功能。

## 本次修复

### 高优先级

- 服务器开奖记录文件名只使用服务器时间和内容哈希生成，客户端时间无法影响文件路径。
- 公开请求不能写入或校验服务器 Cookie 池。只有同时配置并提供独立 `x-cookie-write-key` 的运维请求才具备写权限。
- 后台动态内容继续统一转义；反馈中的 HTML、脚本标签和事件属性只会作为文本显示。
- 500 级错误不再向客户端返回内部路径、上游详情或系统异常信息。

### 滥用与资源限制

- 反馈接口要求 JSON，正文限制为 2 至 1200 字，请求体限制为 16 KB，每个来源每分钟最多 4 次。
- 相同来源的相同反馈在 10 分钟内不能重复提交；匿名来源标识改为带服务器密钥的 HMAC，不保存原始 IP。
- 微博上游响应限制为 4 MB，单次任务最多保留 20,000 位候选。
- 开奖记录最多接受 20 个奖项和 500 位获奖者；候选字段、筛选条件和查询参数均有长度或数量上限。
- 抓取任务、头像缓存、反馈、开奖记录、动作日志和限流表均有容量上限。

### 请求与部署边界

- 生产环境只允许同源或显式配置的跨域来源，不再自动信任任意 localhost 来源。
- 管理后台使用 scrypt 密码哈希、签名会话、HttpOnly/Secure/SameSite Cookie、CSRF Token 和登录限流。
- 增加严格 JSON Content-Type 校验、请求体预检、请求超时、请求头数量上限和异常连接处理。
- CSP 禁止第三方脚本、内联脚本属性、框架嵌入、对象和媒体加载；Caddy 限制请求体并移除 Server 标识。
- systemd 增加最小文件权限、内核保护、SUID/SGID 限制和只读系统目录。

## 仍需部署层配合

- 应在服务器环境文件中设置至少 32 字节的 `ADMIN_SESSION_SECRET`，并设置独立的 `COOKIE_WRITE_KEY`。密钥不得写入仓库或前端配置。
- 应继续使用 Caddy/Nginx 作为唯一公网入口，Node 服务只监听 `127.0.0.1`。
- 应由云防火墙或 CDN/WAF 处理分布式攻击。进程内限流可以限制单一来源，但无法独立抵御大量不同来源的请求。
- CSP 的 `style-src` 仍允许内联样式，以兼容现有图表和动态尺寸；脚本策略不允许 `unsafe-inline` 或 `unsafe-eval`。
