## 已修复的实质问题

| 场景 | 根因与处理 | 回归证据 |
| --- | --- | --- |
| 关闭候选去重后，开奖结果保存失败 | 前端可能让同一用户重复中奖，而后端拒绝重复中奖名单。现在先打乱全部有效转发，再按用户取首次出现；保留每条转发的权重，每位用户本轮最多中奖一次，名额按唯一用户数校验 | `drawPool.test.js`；浏览器使用 3 条转发、2 位用户，3 个名额被拦截，2 个名额成功产生唯一中奖名单 |
| 旧记录重试新增重复开奖记录 | 原实现拒绝超过七天的历史开奖时间，重试使用当前时间生成新哈希。现在沿用有效的历史时间，保持现有未来时间边界和串行写入机制 | 真实 HTTP 测试并发重试三次三十天前记录，文件一致、两次重复响应、开奖时间不变 |
| Windows 下后台事件偶发未保存 | 完整回归与重复复现捕获原子替换返回 `EPERM`。新增仅针对 Windows 短暂占用错误的有界退避，最多等待 775 ms；不删除目标文件，保留原子替换，永久故障仍上报 | `atomic-replace.test.mjs` 验证重试期间旧数据保持完整、成功替换、重试上限及无关错误立即抛出；重复执行微博来源集成测试 |
| 修改访问密钥后状态不刷新，或旧请求覆盖新状态 | 连接与登录态检查分散，取消范围不完整。抽为 `useBackendStatus`，按地址和凭据管理生命周期，取消包括响应正文，输入防抖后自动检查 | 浏览器延迟首次响应，手动检查后旧响应不能覆盖；错误密钥改正后自动恢复 |
| 连接失败、格式异常的错误提示不明确 | 空正文、HTML、非对象 JSON 的处理不一致。统一保留 HTTP 状态和错误来源，区分取消、超时、网络连接失败 | `browserApi.test.js`，设置入口与异常恢复浏览器检查 |
| 异常名单可能使 React 整页报错 | 候选字段未经验证就进入界面。现在在替换名单前检查结构、身份、文本字段和容量 | 无效昵称对象被拒绝，页面继续运行，再次加载正常数据后可以开奖 |
| 未知的历史开奖次数显示为零 | 数值转换把 `null`、空值视为 0。统一使用 `knownDrawCount`，未知状态保持未知 | 单元测试覆盖空值、布尔值、非法数值；确认弹层显示“历史次数暂未核实” |
| 后台退出后导出仍继续 | 顺序导出的请求和限流等待缺少完整取消。抽出 `admin-export.js`，退出时取消、清缓存，并阻止旧会话下载和更新界面 | 单元测试验证取消与响应完整性；后台浏览器在限流等待中退出，确认没有重试或下载 |
| 本机存储不可用时结果容易随刷新丢失 | 离开页面提醒没有覆盖仅在内存中的结果 | 扩展 `beforeunload` 条件；同步失败继续明确提示保存图片或导出名单 |
| 条目数与人数混淆、重复候选列表标识冲突 | 原始转发计数被写为人数，列表复用 UID 作为唯一键。现在结果、公示、图片和候选导出使用条目单位，确认与奖项容量使用用户数，重复条目使用不同列表键 | 名单搜索恢复完整条目；保留原始 3 条抽取证据，结果文案不宣称有 3 位用户；旧记录未保存总数时显示“未记录” |

已移除重复中奖过滤条件进行一次变异验证：对应单元测试失败，恢复修复后通过。
此检查用于确认回归测试确实能捕获该问题。

## 线上报错核查

北京时间 2026-11-04 22:05 的只读快照：线上健康接口报告版本 3.5.1，公开前端、
健康接口及后台登录页均返回 200。进程 RSS 约 117.3 MB，主机可用内存约 1404.9 MB，
采样趋势稳定，存在一个最近验证通过的服务器登录态。这是当时状态，不代表持续可用性保证。

进一步按类别核对，不能把后台所有事件都当作代码错误：

| 观察 | 结论 |
| --- | --- |
| 运行窗口内 5xx 为 0，226 次客户端错误中 222 次路由未命中 | 大量来自外部扫描；没有发现该窗口中的服务端 5xx，但这不能证明业务没有缺陷 |
| 三条 `admin-auth-rejected`，涉及后台概览、记录、反馈读取 | 管理请求鉴权未通过；仅凭日志不能判定是会话过期还是缺少凭据，不应放宽鉴权 |
| 一条 `storage` 事件 | 实际是 `runtime-cache-prune` 成功事件，属于正常缓存回收，不是存储故障 |
| 一条普通 `request` 事件 | 外部路径 `/device.rsp` 使用不支持的方法，返回 405；不是抽奖接口失败 |
| 多次 `provider-incomplete` | 存在微博显示总数 18、接口仅返回 12，以及显示 15929、桌面返回 9847、H5 返回 1194 的情况。接口可见范围受上游及登录态影响，不能据此承诺补齐隐藏记录 |
| GitHub Actions | 核查时最近七次成功，更早一次失败为九月旧记录 |

本次没有向线上提交测试开奖记录、触发真实微博抓取、修改登录态或部署新版本。
诊断摘要、验证日志和截图仅留在已忽略的 `output/` 中，没有把密钥、Cookie、
私有后台入口或生产运行日志写入本文。
