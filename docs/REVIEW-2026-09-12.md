## 三、上一步改动的可行性复核

上一轮改了滚动区域键盘可达性和结果弹层的焦点返回，今天的结论是**可行，保留**：

- 侧边弹层只有在内容真的溢出时才加 `tabIndex`/`role="region"`，键盘可以把
  列表滚动到底部，鼠标用户看不到任何区别。
- 结果弹层关闭后，焦点会回到触发它的按钮；如果原按钮已经不存在，再退回页面
  导航，不会出现“焦点丢失到页面顶部”。
- `ResizeObserver`/`MutationObserver` 在目标浏览器上兼容，只在弹层打开期间
  运行，开销可以忽略。
- 定向无障碍扫描中“可滚动区域无法聚焦”的问题数量为 0。

## 四、完整审查后发现并修复的问题

### 1. 部署默认值会让整站 401（本次最重要）

**现象**：安装脚本会给服务器随机生成一个 `API_KEY`，并把同一个密钥写进浏览器
能下载到的 `config.js`。但前端是放在 GitHub Pages 的静态页面，读不到服务器下发
的这份配置，于是服务器要求密钥、前端没有密钥，访客载入候选、保存记录全部失败。

**修法**：新安装默认写 `ALLOW_PUBLIC_API=1`，不再生成 `API_KEY`。真正需要访问
门槛的私有部署仍然可以手动配置 `API_KEY`，但必须把同一个值同步到所有前端分发
渠道。浏览器能读到的密钥本来就不是保密凭据，它可以挡掉顺手抓接口的人，挡不住
有意滥用的人。

### 2. 后端要求密钥时，页面说不清怎么办

**现象**：以前只会弹一句“访问密钥不正确或未提供”，普通用户不知道去哪里填。

**修法**：`/api/health` 现在会说明这个后端是否需要密钥；设置页“后端连接”里会
直接提示“当前后端开启了访问密钥校验”，候选载入遇到 401 时会告诉你到设置里填写
后重新载入。

### 3. 同一个 IP 下用户互相抢限流额度

**现象**：所有 GET 接口只按 IP 计数。学校、单位或运营商 NAT 后面可能有几十个
人共用一个出口 IP，一个人多刷几次，其他人就会收到“请求过于频繁”。

**修法**：改成按“浏览器标识”计数，同时保留一个更宽松的 IP 上限，防止伪造标识
绕过限流。正常情况下同一个网络里的用户不再互相拖累，滥用仍然会被 IP 总上限拦住。

## 五、确认保留的安全防护

这次审查没有为了“好用”削掉真正有用的防护，以下全部保留：

- 后台账号、会话、CSRF 校验和登录失败限速；
- 后台页面所有用户数据输出都做 HTML 转义，外链只允许微博域名；
- 微博登录态（Cookie）池的读写密钥、隔离和审计，Cookie 内容不写日志；
- 头像代理的域名白名单、DNS 私网检查和禁止重定向（防 SSRF）；
- 请求体大小、候选数量、开奖名额、反馈条数和存储容量的上限；
- 抓取任务队列、并发上限、分页延迟，避免把微博接口和服务器打爆；
- 页面 CSP、防点击劫持、`nosniff`、不发送来源信息等响应头。

## 六、速度核查结果

用生产构建产物实测（Brotli 压缩后）：

- 主程序 60 KB、React 45 KB、样式 25 KB，首屏合计约 125 KB；
- 手机正常网络首次内容绘制约 0.46 秒；桌面约 0.15 秒；
- 模拟慢速 4G 加 4 倍 CPU 降速，首次内容绘制约 1.35 秒，没有超过 200 ms 的
  长任务。

结论是当前不需要为了体积做高风险的分包改造。已有的优化（React 与结果图、
法律文本分包，非当前标签页不挂载，搜索输入延迟渲染，静态资源 Brotli/ETag/
长缓存，头像预加载）已经够用。

## 八、补充修改（同日晚些时候）

### 1. 前端不再显示真实后端地址

设置页原来会把配置好的服务器地址明文写在输入框里。现在默认只显示一句“已使用
预置服务地址，默认不在页面上显示”，连接成功与失败提示也不再回显地址；只有用户
主动点“手动填写地址”时才出现输入框，用来连接本机或自建服务。预置地址不再写进
浏览器本地存储，本地存储里只保留用户自己填过的自定义地址。

### 2. 后台入口路径可以改名

新增环境变量 `ADMIN_BASE_PATH`（默认 `/admin`）。改成例如 `/ops-9d2c` 之后，
旧地址不会再返回后台页面，后台相关的脚本资源也只在新的路径下可用；路径写法不
合法（比如占用 `/api`）时服务会拒绝启动。前端页面本身不链接后台入口。

两项改动都补了回归测试：前端界面测试确认默认不显示地址，新增的服务端测试确认
自定义后台路径可用、默认路径不再暴露后台页面、非法路径会被拒绝启动。
