# 代码结构与开发约定

这是一个 React 单页应用与 Node.js 服务端共用的仓库。前端可独立部署为静态站点；
Node 服务负责微博抓取、运行数据、后台管理，也能提供构建后的静态文件。

## 目录与职责

| 路径 | 职责 |
| --- | --- |
| `src/App.jsx` | 应用业务编排：抓取、筛选、开奖、保存和历史同步 |
| `src/components/AppWorkspace.jsx` | 工作区页面、导航和页面内展示状态 |
| `src/components/sheets/` | 业务弹层，通过数据与回调声明依赖 |
| `src/components/ui/` | 弹层容器、通知、确认框、图标等界面基础组件 |
| `src/hooks/` | 与 React 生命周期和交互绑定的逻辑 |
| `src/hooks/useBackendStatus.js` | 按后端地址与访问密钥管理连接检查、取消过期请求 |
| `src/hooks/useDrawCount.js` | 按来源、链接、后端和凭据隔离次数查询；载入与保存结果取消旧查询 |
| `src/lib/repostResponse.js` | 在候选进入界面前校验数据，区分未知次数与零次 |
| `src/lib/drawPool.js` | 统计可抽用户，并在打乱转发条目后保证单轮中奖唯一 |
| `src/lib/browserApi.js` | 浏览器后端配置、可信地址和请求生命周期 |
| `src/lib/` | 开奖、候选、记录、诊断等领域逻辑及环境辅助模块 |
| `src/styles/` | 设计变量、布局、抽奖舞台、组件、动效和统一主题；由 `main.jsx` 明确导入顺序 |
| `server.mjs` | 服务配置、HTTP 路由、任务编排、存储及浏览器生命周期 |
| `server/weibo/` | 候选集合不变量、微博响应与页面解析 |
| `server/weibo/response-policy.mjs` | HTTP、业务状态、登录页面与转发列表结构校验，不持有凭据或发起网络请求 |
| `server/security/` | 服务端网络访问策略 |
| `server/http/` | 静态文件缓存、压缩和条件请求 |
| `server/storage/` | 原子文件替换及 Windows 短暂占用的有界重试 |
| `server-admin/` | 独立后台页面；少量共享模块由服务端白名单映射提供 |
| `server-admin/admin-export.js` | 顺序导出记录、限流退避和会话取消 |
| `scripts/` | 构建、验证和本地开发工具 |
| `deploy/` | 服务安装、反向代理和服务进程配置 |
| `static/` | 构建时直接复制的公开资源与站点配置 |

## 模块边界

界面组件优先接收明确的数据和回调。网络地址与请求超时、取消、正文读取的生命周期
统一由浏览器 API 模块处理；业务弹层不直接实现另一套请求或持久化流程。

后端解析模块接收响应数据并返回领域对象，不持有 Cookie、HTTP 请求或全局任务状态。
候选数量、字节预算与去重由同一个集合模型维护，分页、首页补查和备用入口共用该模型。
网络请求、登录态、任务排队与持久化由服务编排层负责。

微博请求只读取重定向状态与目标，不跟随跳转；错误分类覆盖响应头、正文读取与解析的
整个生命周期。HTTP 200 但内容不合法也视为上游失败，不能伪装成空名单。
明确的分页失败会保留此前候选并尝试备用入口；这种情况下数量容差不能证明扫描完成，
只有聚合结果实际补足已知总数后才恢复完整标记。非异常分页保留原有显示总数容差策略。

共用逻辑按用途命名并通过直接 import 复用。浏览器模块不得导入 Node 内置模块；
环境相关逻辑应有明确入口，不通过增加一层通用工具或桶导出掩盖依赖。

样式由 `tokens.css`、`layout.css`、`draw.css`、`components.css`、`motion.css` 和
`theme.css` 依次载入。统一主题集中定义颜色、材质和控件尺寸，通过 `.studio-app`
限定工作区与弹层的作用范围。新视觉规则优先使用 `--studio-*` 变量；响应式、深色、
减少动效、降低透明度和系统高对比模式的覆盖集中放在主题尾部，避免页面各自维护一套配色。
页面使用纯色背景，流程条只展示实际的名单、奖项确认和开奖进度。

## 测试与构建

```powershell
npm test
npm test -- --test-name-pattern="candidate"
npm run build
npm run test:release
```

单元测试放在实现旁，命名为 `*.test.js` 或 `*.test.mjs`。测试入口自动扫描
`src/`、`server/`、`server-admin/` 和 `scripts/`，不会执行 `output/` 中的运行数据，
也不会把 `scripts/test-*.mjs` 集成流程混入普通单测。

HTTP、服务生命周期、浏览器、内存和 UI 测试由完整发布检查串联执行。测试中的
等待退出与进程清理由 `scripts/child-process.mjs` 管理；成功、失败和取消都必须
释放计时器、监听和自己创建的进程。

新增 Node 运行模块时同步检查部署 stage 的必备文件清单；新增后台浏览器模块时，
同步检查后台资源白名单。运行数据、登录资料和密钥不属于源码或构建产物。

## 业务不变量

关闭候选去重时，摘要与随机排序仍使用全部有效转发条目；排序后按用户取首次出现，
保证每位用户每轮最多中奖一次。奖项容量按唯一用户数检查，原始条目保持不变。

开奖记录重试沿用有效的原始开奖时间，不能因记录变旧而重新生成标识。写入继续通过
已有的串行门控与原子文件持久化处理，避免追加重复锁或改变现有记录格式。

设置弹窗独立维护展开与滚动状态。连接检查在地址或密钥变化、卸载时取消旧请求；
后台导出的取消覆盖网络请求和限流等待，并在退出会话后清理详情缓存。
